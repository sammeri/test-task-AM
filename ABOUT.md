# Нагрузочное тестирование API (Frontend + Backend)

## Это мой полноценный проект для нагрузочного тестирования API, включающий:

### Frontend — Vue 3 + Web Workers

### Backend — NestJS

### Database — PostgreSQL

### Infrastructure — Docker

Проект позволяет воспроизводить реальную нагрузку на API, анализировать отклик, масштабируемость и стабильность сервиса.

# Возможности приложения
## Regular Test

Обычный тест, работающий в основном UI-потоке.

Я использую его для:

- проверки базовой нагрузки

- тестирования API в последовательном и параллельном режиме

- наблюдения, как UI реагирует на большое количество запросов

- получения мгновенной статистики

## Функции:

- ввод количества запросов

- задание concurrency

- лог запросов

статистика в реальном времени

## Worker Test

Реализован вариант нагрузочного тестирования через Web Worker.

Задачи, которые Worker решает:

- UI остаётся полностью отзывчивым

- можно отправлять десятки тысяч запросов

- scheduler оптимизирован под высокую конкуренцию (до 500–1000)

- немедленный отклик с первыми результатами

## Backend: NestJS

Backend также разработан и используется в нагрузочных тестах.

### Основные элементы:

- Контроллер GET /items/:id

- Контроллер GET /count

- PostgreSQL в Docker

- Пул соединений через TypeORM

API возвращает записи из таблицы items по ID, что идеально подходит для стресс-тестов с рандомными запросами.

## PostgreSQL + Docker

Поднял PostgreSQL в Docker и использовал его в нагрузочных сценариях.

### Настроено:

- Docker-контейнер с postgres

- Взаимодействие через TypeORM

### Индексация

PostgreSQL автоматически создаёт индекс по:

PRIMARY KEY (id)

Это обеспечивает:

O(log N) доступ к записям

быструю выборку случайных ID

устойчивость к нагрузке

При конкуренции 500–1000 запросов/сек индекс даёт стабильный отклик, что подтвердили тесты.

## Оптимизация, которую я реализовал
### Frontend

- вынес нагрузку в Web Worker

- создал кастомный scheduler (сразу запускает следующий запрос)

- уменьшил количество перерисовок UI

- оптимизировал логирование

- добавил real-time статистику без лагов

### Backend (NestJS)

- использовал пул соединений TypeORM

- разнёс контроллеры и сервисы

- настроил корректную обработку JSON

- оптимизировал структуру роутов

- минимизировал задержки в ответах

### PostgreSQL

- использовал автоматический индекс по id

- поднял max_connections под нагрузку

## Что ещё можно улучшить

- тюнинг shared_buffers, work_mem, wal_buffers

- настройка autovacuum для больших таблиц

- включение pg_stat_statements для анализа запросов

### Кэширование через Redis
- мгновенные ответы для горячих данных
- разгрузка PostgreSQL

### Мониторинг

Добавить:

метрики CPU, RAM, I/O

отслеживание долгих запросов
